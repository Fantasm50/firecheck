# Запуск прототипа «Веб-сервис самопроверки пожарной безопасности объекта»

Прототип работает на любом ПК (Windows, macOS, Linux) с Python 3.12+ и в облаке. Данные объекта никуда не записываются: ответы обрабатываются на сервере, где запущен сервис (при локальном запуске — ваш компьютер, в облаке — сервер хостинга), и живут только до закрытия вкладки. В облачной версии не вводите реальные данные предприятия.

Демо-объект — производство (цех, мастерская), 60 требований из ППР № 1479 и проверочного листа приказа МЧС № 525. Отчёт обязательно содержит предупреждения (стадия прототипа, баллы черновые, ППР действуют до 31.12.2026).

## 1. Любой компьютер (Windows / macOS / Linux)

```bash
cd <папка проекта>
python3 -m venv .venv
# Windows:  python -m venv .venv

.venv/bin/pip install -r requirements-deploy.txt
# Windows:  .venv\Scripts\pip install -r requirements-deploy.txt

.venv/bin/streamlit run app.py
# Windows:  .venv\Scripts\streamlit run app.py
```

Откроется http://localhost:8501. Закрыть — Ctrl+C в терминале.

Полная среда разработки (с pytest и тестами): `requirements.txt`, тесты — `pytest`.

## 2. Облако Streamlit Community Cloud (основной вариант для демо)

Приложение — один файл `app.py`, зависимости — в `requirements-deploy.txt`. Кода под конкретный cloud нет.

1. Загрузите папку в репозиторий GitHub (уберите `.venv`, `.pytest_cache`, `__pycache__`, `sources/`, `.docx/.pptx/.pdf` — см. `.gitignore`/`.dockerignore`). Обязательно: `app.py`, `core/`, `*.yaml`, `requirements-deploy.txt`, `.streamlit/config.toml`.
2. На [share.streamlit.io](https://share.streamlit.io) → New app → выберите репозиторий, ветку и `app.py` как main file.
3. Зависимости Streamlit Cloud подхватит из `requirements-deploy.txt` автоматически. Он создаёт виртуальное окружение и ставит пакеты — ничего доустанавливать не нужно.
4. Приложению не нужен секреты-файл: API-ключей и БД нет, ответы живут только в памяти сервера на время сеанса.
5. Ссылка вида `https://<app>.streamlit.app` — её и показывать на демо (запасной вариант — локальный запуск, он работает без интернета).

Notebook: `app.py` не требует правок под облако: пути к YAML строятся относительно самого файла, локальных путей и секретов нет.

## 3. Docker (запасной вариант, любой сервер/VPS)

```bash
docker build -t firecheck .
docker run -p 8501:8501 firecheck
```

Откроется http://localhost:8501 (на сервере — http://<адрес сервера>:8501). Образ собирается из `requirements-deploy.txt`, в контейнер копируются только `app.py`, `core/` и базы YAML (см. `.dockerignore`).

## Структура

- `app.py` — интерфейс Streamlit (анкета → чек-лист → результат);
- `core/` — загрузка YAML-баз, чек-лист, расчёт (FMEA, индекс готовности), отчёт DOCX;
- `requirements_production.yaml`, `checklist_525.yaml`, `scores_production_draft.yaml` — демо-база (производство); `requirements_warehouse.yaml`, `scores_warehouse_draft.yaml` — склад (после демо);
- `core/validity.py` — сроки действия актов, на которых стоит база (ППР № 1479 — по 31.12.2026, пост. № 1464 — по 28.02.2027); даты в `requirements_production.yaml`, раздел `meta.validity`;
- `core/sources.py`, `data/sources_lock.yaml` — сверка пунктов базы с текстом ППР (см. ниже);
- `tests/` — pytest, запуск: `pytest`.

## Актуальность базы норм

**Срок действия.** За 30 дней до последнего дня действия акта и после него приложение и отчёт показывают предупреждение, а тест `test_base_is_in_force_today` после этой даты падает: так устаревшая база не используется молча. Сами нормы программа не обновляет.

**Сверка с текстом ППР.** Для каждого пункта ППР, на который ссылается база, в `data/sources_lock.yaml` хранится «отпечаток» его текста в той редакции, с которой база сверена вручную. Когда выйдет новая редакция:

1. Скачайте её в формате .docx и положите в папку `sources/`.
2. Запустите сверку (показывает, какие пункты ППР изменились или пропали и какие пункты базы на них опираются; ничего не меняет):
   ```bash
   .venv/bin/python -m core.sources sources/<новый_файл>.docx
   ```
3. Перечитайте каждый найденный пункт базы по новому тексту и исправьте `requirements_production.yaml`.
4. Только после ручной сверки сохраните новые отпечатки (перезаписывает `data/sources_lock.yaml`):
   ```bash
   .venv/bin/python -m core.sources sources/<новый_файл>.docx --update
   ```

Программа находит изменения в тексте, но не решает, верно ли база их отражает: это делает специалист. Пункты без ссылки на ППР (DOC-*, SYS-*) сверяются вручную.
