## 1. Цель прототипа

Показать на демо-дне полный путь: специалист описывает производственный объект (цех, мастерскую), отвечает на чек-лист и получает отчёт с индексом готовности и реестром нарушений по приоритету. Сценарии: регулярный внутренний контроль, подготовка к обязательному профилактическому визиту или проверке МЧС.

Прототип — это демонстрация методики, а не продукт для реальной эксплуатации. Нормы взяты из ППР № 1479, а они действуют до 31.12.2026, поэтому отчёт обязательно содержит предупреждение об этом.

## 2. Пользователь

Ответственный за пожарную безопасность или специалист службы ОТ и ПБ предприятия с производственным объектом (размер предприятия не ограничен). Работает один, с компьютера, без регистрации.

## 4. Функции

**4.1. Анкета объекта (производство).** Анкета покрывает все условия (`condition`) 32 условных пунктов демо-набора (29 + SYS-001…003 с 2026-11-17). Имя флага в скобках — для поля `applies_if`.

*Общие сведения:* название (необязательно); площадь, м²; этажность; наивысшая категория помещений по взрывопожарной и пожарной опасности (А, Б, В1–В4, Г, Д) (`category`); наибольшее число людей в здании одновременно (`people_max`); наибольшее число постоянных рабочих мест на этаже (`workplaces_per_floor`).

*Системы противопожарной защиты (да / нет):*
- АПС (`has_aps`), СОУЭ (`has_soue`), АУПТ (`has_aupt`);
- внутренний противопожарный водопровод (`has_indoor_hydrants`);
- обязано ли здание по нормам иметь внутренний водопровод или АУПТ: да / нет / не знаю (`water_required`: `yes` / `no` / `unknown`, по умолчанию `unknown`; подсказка «смотрите проектную документацию»). Нужен для исключения п. 410 (EXT-005);
- обязано ли здание по нормам иметь АПС, СОУЭ, АУПТ: да / нет / не знаю (`aps_required`, `soue_required`, `aupt_required`, по умолчанию `unknown`; добавлено 2026-11-17). Если системы нет, а ответ не «нет», показывается пункт SYS-001, SYS-002 или SYS-003 (флаги `aps_missing`, `soue_missing`, `aupt_missing`). Программа сама не решает, нужна ли система: по пост. № 1464 (прил. 1, 3, 5) это зависит от категории и площади каждого помещения и от даты ввода здания; подсказки в анкете и в поле `note` пунктов. Закрывает слепую зону: раньше объект без обязательной АПС отвечал «не применимо» на GEN-033, GEN-034, и нарушение терялось (review-expert-panel-2026-11-17.md §5);
- пожарные насосы или задвижки с электроприводом (`has_fire_pumps`);
- наружное противопожарное водоснабжение в зоне ответственности (`has_outdoor_water`);
- пожарный пост или диспетчерская (`has_fire_post`);
- огнезадерживающие клапаны в воздуховодах (`has_fire_dampers`);
- наружные пожарные или эвакуационные лестницы, ограждения кровли (`has_external_stairs`);
- огнезащита конструкций (`has_fire_retardant`);
- системы эксплуатируются сверх срока службы или нет данных изготовителя (`systems_over_life`).

*Технология и отопление (да / нет):*
- применяются пожаро- и пожаровзрывоопасные вещества (`uses_hazardous_substances`);
- работа с маслами, лаками, красками, ЛВЖ и ГЖ (`uses_oils_paints`);
- вытяжные устройства, аппараты, трубопроводы с пожароопасными отложениями (`has_exhaust_deposits`);
- пылесборные камеры, циклоны (`has_dust_collectors`);
- искрогасители, молниезащита, защита от статического электричества на оборудовании (`has_ignition_protection`);
- огнепреградители (`has_flame_arresters`);
- печи, котельные, калориферы (`has_heating_units`); котельная или теплопроизводящая установка (`has_boiler`);
- проводятся огневые работы (`does_hot_work`); огневые работы на технологическом оборудовании (`hot_work_on_equipment`).

*Документы (да / нет):* проектная документация (`has_design_docs`); обоснование через расчёт пожарного риска, исследования или испытания (`uses_risk_calc`); СТУ или стандарт организации (`has_stu`); объект подлежит декларированию (`needs_declaration`, с подсказкой «уточнить критерии по ст. 64 123-ФЗ»).

Правило `applies_if`: пункт включается, если истинен **хотя бы один** флаг из списка. Три флага вычисляются в коде из анкеты:
- `many_people` = `people_max >= 50` или `workplaces_per_floor >= 10` (GEN-003, планы эвакуации, п. 5);
- `mass_people` = `people_max >= 50` (GEN-004, тренировки, п. 9);
- `no_water_no_aupt` = нет `has_indoor_hydrants`, нет `has_aupt` и `water_required` не равно `no` (EXT-005, вместе с `does_hot_work`). При `unknown` пункт показывается с подсказкой из поля `note`. Территории без наружного водоснабжения и наружные установки дальше 100 м от водоисточника в демо не спрашиваем.

PROD-005 — `has_ignition_protection`, `has_flame_arresters` или `has_dust_collectors`; GEN-026 — `has_fire_dampers`, `has_aps` или `has_aupt`. Флаг `has_soue` в `applies_if` не используется (GEN-024, GEN-034 включаются всегда), он нужен для титула отчёта и кейсов.

**Ограничения демо (записать в отчёт и питч, если спросят):** наряд-допуск на огневые работы (п. 372) не проверяется — граница с проектом № 1; п. 77 (проверка отопления перед сезоном) показывается только при собственных печах, котельной или калориферах, хотя буквально касается любых отопительных систем.

**4.2. Генерация чек-листа.** Сервис включает пункт, если его условие выполняется по анкете. Пункты без условия (`condition: null`) включаются всегда (31 из 60). В демо попадают только пункты с `demo: true`.

**4.3. Заполнение.** По каждому пункту ответ: «соответствует», «не соответствует» или «не применимо». Для «не применимо» комментарий обязателен (как в форме приказа № 525). Для «не соответствует» можно добавить комментарий. Пункты сгруппированы по 8 темам экрана (таблица в 4.10). Внутри темы пункты идут в порядке файла `requirements_production.yaml`, темы — в порядке таблицы 4.10. Над списком счётчик «отвечено N из M».

**4.4. Баллы S, O, D и повышение O.** Для каждого несоответствия берутся базовые S, O, D из файла баллов. Специалист может поднять O на 1 (не выше 5), если нарушение массовое или постоянное; причину нужно указать. S и D специалист не меняет.
- Для каждого нарушения хранятся `o_base`, `o_raise` (0 или 1) и `o_reason`. Если `o_raise = 1`, причина обязательна (не пустая после удаления пробелов), иначе ответ не сохраняется. Если `o_base = 5`, поднять O нельзя (кнопка неактивна).
- Эффективное O = min(5, `o_base` + `o_raise`). По нему считаются группа, порядок, клетка матрицы в отчёте и топ-5.
- RPN хранится дважды: `rpn_base` = S × `o_base` × D и `rpn_eff` = S × эффективное O × D. Для сравнения с экспертами в научной части берётся `rpn_base`: эксперты оценивают базовые баллы.

**4.5. Приоритет** (правило принято 2026-10-20):
1. Группа по таблице S × O: высокий, средний, низкий. S = 5 всегда «высокий». Источник истины — таблица `priority_matrix` из файла баллов, а не формула: группа = `priority_matrix[S][O − 1]`, значения H, M, L.
2. Порядок в отчёте (уточнено 2026-10-21, замечание К3 в review-scales.md): группа (высокий → средний → низкий) → сначала S = 5 → S × O по убыванию → S по убыванию (при равном S × O тяжесть важнее) → D по убыванию (скрытые выше) → id по алфавиту (чтобы порядок был однозначным). Ключ «пункты из листа № 525 выше» убран: метка `q525` есть у всех пунктов и ничего не различает.
3. RPN = S × O × D считается и сохраняется, но в интерфейсе по умолчанию не показывается (нужен для научной части).

**4.6. Показатели.**
- **Индекс готовности** = соответствует / (соответствует + не соответствует) × 100 %. Ответы «не применимо» не учитываются. Округление до 1 знака, половина вверх (`Decimal`, `ROUND_HALF_UP`). Если «соответствует» + «не соответствует» = 0 (всё «не применимо»), функция возвращает `None`: на экране «—» и текст «Нет пунктов с оценкой: индекс не считается», отчёт всё равно формируется. Рядом с индексом показывается число ответов «не применимо».
- **Критические нарушения** (добавлено 2026-11-17 по review-expert-panel-2026-11-17.md §5): нарушения с S = 5 («угроза жизни» по шкале S в [fmea-scales-draft.md](fmea-scales-draft.md)), в порядке правила 4.5. Их число показывается **выше индекса и крупнее**: индекс считает все пункты одинаково, и один запертый выход даёт 97,4 % (Т11). Рядом с индексом — число нарушений по группам приоритета (высокий, средний, низкий).
- **«Не применимо» у безусловных пунктов** (пунктов без `applies_if`, то есть обязательных для всех объектов): перечень показывается отдельным предупреждением, потому что такие пункты не входят ни в индекс, ни в реестр нарушений (например, GEN-033 и GEN-034 на объекте без АПС, 4.9.3).
- **Покрытие листа № 525:** показываются 10 вопросов из `prototype_scope.production` в [checklist_525.yaml](../checklist_525.yaml) и строка «Остальные 17 вопросов листа в прототипе не проверяются». Статус вопроса определяется **строго в этом порядке** (первое выполненное условие):
  1. «нет пунктов в базе» — в базе нет ни одного демо-пункта с этим `q525` (сейчас таких вопросов нет);
  2. «к объекту не относится (по анкете)» — в чек-лист не попал ни один пункт вопроса;
  3. «есть нарушения» — хотя бы один ответ «не соответствует»;
  4. «все пункты не применимы» — все ответы «не применимо»;
  5. «все пункты соответствуют» — остальные случаи.

  Порядок важен: для пустого списка проверка «все ответы не применимо» в Python формально истинна (`all([])` возвращает `True`), поэтому пустые вопросы отсекаются первыми (исправлено 2026-10-21 по final-check.md).

**4.7. Отчёт (DOCX).** Титул: объект, дата, версия базы норм. Затем число критических нарушений со ссылками на пункты, индекс готовности, число нарушений по группам приоритета, перечень «не применимо» у безусловных пунктов (4.6), матрица 5 × 5 с числом нарушений в клетках, топ-5 нарушений, полный реестр нарушений (пункт ППР — поле `ppr`, а если оно пустое, как у DOC-002…005, — поле `source`; требование, S, O, группа, поле «срок устранения» и «ответственный» для заполнения), покрытие листа № 525, строка «По анкете скрыто пунктов: N» и предупреждения (раздел 7). PDF — после демо.
- **Топ-5** — первые 5 нарушений списка, отсортированного по 4.5 (порядок однозначный, ничьих нет). Если нарушений меньше 5, показываются все; если их нет — текст «Нарушений не выявлено».
- Кнопка «Сформировать отчёт» неактивна, пока есть пункты без ответа.

**4.8. Экран результата** (для питча): статус «Критических нарушений: N» (красный) или «Критических нарушений нет» (зелёный), под ним индекс готовности крупным числом и число нарушений по группам, топ-5 нарушений со ссылками на пункты ППР, затем матрица 5 × 5 как второстепенный блок. Один экран без прокрутки на ноутбуке. В подписях писать «приоритет нарушений», а не «оценка рисков» (разграничение с проектом № 2).

**4.9. Правила обработки и проверки данных** (приняты 2026-10-21 по spec-gaps.md).
1. **Анкета.** `people_max` и `workplaces_per_floor` обязательны, целые, не меньше 0. Пока поле пустое, анкету нельзя отправить. Флаги «да / нет» по умолчанию «нет», `water_required`, `aps_required`, `soue_required`, `aupt_required` по умолчанию `unknown` (осторожный вариант: EXT-005 и SYS-* показываются с подсказкой).
2. **Пункт с ложным условием** (не прошёл `applies_if`) не показывается и нигде не учитывается: ни в индексе, ни в покрытии, ни в ответах. В отчёте только счётчик скрытых пунктов.
3. **«Не применимо»** разрешено для любого пункта, в том числе без условия, но комментарий обязателен (не пустой после удаления пробелов), иначе ответ не сохраняется. Это соответствует форме приказа № 525 (примечание обязательно при «неприменимо»). Допустимо ли «не применимо» по существу для конкретного пункта ППР, программа не решает. Например, GEN-033 и GEN-034 (системы защиты) остаются безусловными: на объекте без АПС на них отвечают «не применимо» с комментарием. Само отсутствие обязательной АПС, СОУЭ или АУПТ с 2026-11-17 проверяют пункты SYS-001…003 (4.1).
4. **Ошибка загрузки** (программа не запускается и пишет, что не так в файлах), если:
   - id повторяется;
   - у демо-пункта нет записи в `scores` или в `scores` есть id, которого нет среди демо-пунктов (в тексте ошибки — список id);
   - S, O или D не целое от 1 до 5;
   - `priority_matrix` неполная: не 5 строк (S = 1…5), не по 5 значений, или значение не H, M, L;
   - флаг из `applies_if` не входит в список флагов анкеты 4.1 (включая вычисляемые `many_people`, `mass_people`, `no_water_no_aupt`);
   - у демо-пункта `condition` не null, а `applies_if` пуст;
   - `q525` нет в `checklist_525.yaml`;
   - `topic` нет в таблице тем 4.10.

**4.11. Актуальность базы норм** (добавлено 2026-11-18 по review-expert-panel-2026-11-17.md §2 п. 5).
1. **Срок действия.** В `meta.validity` файла `requirements_production.yaml` для каждого акта записаны последний день действия (`last_day`), основание и какие пункты на нём стоят (`items: ppr` — пункты с полем `ppr`; иначе — пункты, в поле `source` которых есть этот текст). Сейчас: ППР № 1479 — 31.12.2026 («до 31 декабря 2026 г. включительно»); пост. № 1464 — 28.02.2027 («до 1 марта 2027 г.», последним днём принято 28.02 — осторожное прочтение «до»). За 30 дней до `last_day` экран анкеты, экран результата и раздел «Важно» отчёта показывают предупреждение, после `last_day` — ошибку. Тест `test_base_is_in_force_today` после `last_day` падает.
2. **Сверка с текстом ППР.** `data/sources_lock.yaml` хранит отпечаток (SHA-256, 16 знаков) текста каждого пункта ППР, на который ссылается база, в редакции, с которой база сверена вручную. Текст пункта — абзацы от «N.» до следующего пункта, без строк «(в ред. …)», заголовков разделов и приложений; пробелы и «ё» нормализуются. Команда `python -m core.sources <файл.docx>` перечисляет пункты ППР, текст которых изменился или которых нет в источнике, и пункты базы, которые на них опираются. Отпечатки обновляются (`--update`) только после ручной сверки. Пункты без ссылки на ППР (DOC-*, SYS-*) сверяются вручную. Программа находит изменения, но не решает, верно ли база их отражает.

## 6. Технологии

- Python 3.11 или новее, Streamlit (интерфейс), PyYAML (чтение баз), python-docx (отчёт).
- Почему Streamlit: интерфейс пишется на чистом Python без HTML и JavaScript, это быстрее всего для новичка. Расчётная логика отдельно от интерфейса, чтобы позже перейти на FastAPI.
- Окружение: виртуальное окружение `.venv` в папке проекта и `requirements.txt` (`streamlit`, `PyYAML`, `python-docx`, `pytest`); версии фиксируются `pip freeze` после установки. Устанавливать только с согласия пользователя.
- Структура:

```
app.py            # Streamlit screens
core/loader.py    # read YAML bases and check them (4.9.4)
core/checklist.py # build checklist from questionnaire
core/scoring.py   # groups, ordering, readiness index, RPN
core/report.py    # DOCX report
data/themes.yaml        # topic -> screen theme (4.10)
data/questionnaire.yaml # questionnaire flags and labels (4.1)
tests/            # pytest tests, incl. reference tests 8.2
pytest.ini        # pytest settings
```

- Базы норм и баллов (`requirements_production.yaml`, `scores_production_draft.yaml`, `checklist_525.yaml`) читаются из корня проекта, **без копий** в `data/`: копии разошлись бы с оригиналами (решение 2026-10-21). Пути заданы в `core/loader.py` (`DEFAULT_PATHS`), тесты подставляют свои.
- Запуск тестов: `.venv/bin/python -m pytest` из папки проекта.

- Данные предприятия не записываются на диск: ответы живут только в текущем сеансе, отчёт скачивается. В репозиторий и примеры — только синтетические данные.

**6.1. Размещение прототипа в сети** (2026-11-19, service-roadmap.md П0).
- **Адрес:** https://fantasm50.github.io/firecheck/ — публичный репозиторий https://github.com/Fantasm50/firecheck (код без личных файлов, лицензия «All rights reserved»).
- **Как работает:** статическая страница `index.html` на GitHub Pages загружает **stlite** (Streamlit, собранный под **Pyodide** — Python в браузере на WebAssembly; stlite 1.12.0 содержит Streamlit 1.65). Тот же `app.py` и `core/` выполняются **в браузере пользователя**: сервера с Python нет, ответы не покидают устройство. Бесплатно, не «засыпает», открывается из российских сетей (проверено 2026-11-19).
- **Отличия от локального запуска:** первая загрузка до минуты (браузер скачивает Python и пакеты `python-docx`, `pyyaml`); отчёт отдаётся ссылкой `data:` вместо кнопки скачивания (кнопка Streamlit в stlite не работает); плашка на экране сообщает, где обрабатываются ответы (`IN_BROWSER` в `app.py`).
- **Почему так, а не иначе:** Streamlit Community Cloud не пустил аккаунт (`policy_denied`, вероятно ограничение по региону); на Hugging Face Spaces запуск Docker теперь только платный. Платная альтернатива — российский VPS с Docker-образом (Dockerfile готов); вариант для пилота с реальными данными — установка у предприятия или на сервере вуза.
- **Как обновлять:** `.venv/bin/python tools/export_public.py` (собирает чистую копию `public-export/` и `index.html`, проверяет на личные данные), затем в `public-export/` — коммит и `git push`; сайт обновляется примерно через минуту.
- **Локальный запуск** (без интернета): `.venv/bin/streamlit run app.py`.
